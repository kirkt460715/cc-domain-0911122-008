# 营业日采集网关

## 基础协议
运行 `python3 -m lab.provider`（旧版合成来源）或 `python3 -m lab.collection_provider`（采集计划演示网关）。
两者都只监听回环地址，不连接生产服务。`GET /readings` 的 `meter`、`segment`、`start`、`end` 参数指定表计、安装段与带 UTC 偏移的左闭右开区间，按小时返回合成读数；`limit` 控制单次最多返回条数。

覆盖证据规则（关键）：

- `complete=true` 且 `coverage` 非空时，才表示服务确认覆盖了整个请求区间；
- 只有若干 `rows` 但 `complete=false`、`coverage=null` 时，几条读数不等于全覆盖，采集端不会把该区间记为已拥有；
- 因此空响应或截断响应永远不会自动证明覆盖。

## 采集演示网关 lab.collection_provider.CollectionProvider
时钟可注入（构造时传入零参数 callable，或 `POST /admin/clock`），数据只保留“当前时间之前”的部分，未来时间点没有读数，便于不等待真实营业日就演示调度。

管理接口：

| 接口 | 作用 |
| --- | --- |
| `POST /admin/clock` `{"at": <epoch>}` | 注入网关当前时间 |
| `POST /admin/gap` `{"start","end"}` | 声明来源侧真实数据缺口，缺口内无读数且阻断覆盖证据 |
| `POST /admin/down` `{"start","end"}` | 声明停机时段，与请求区间相交即返回 503 |
| `GET /requests` | 查看实际请求过的区间，用于和采集计划对账 |
| `POST /admin/reset` | 清空注入状态与请求记录 |

合成计划 `fixtures/calendar.json` 包含纽约春季、秋季切换及跨午夜营业日，时区信息由运行环境的 IANA 数据提供。`GET /readings` 的完整行为测试见 `tests/test_collection_gateway.py`。
